# 云数中台设计方案

## 一、项目概述

### 1.1 项目背景

云数中台是公司统一汇聚舆情等数据的入口。领导沟通后，本期优先保证**后端数据能汇总进入云数中台**；分析统计类能力后续再规划深化。**现有已落地的相关功能模块保持不变**，可先继续使用并在有数后自然接上汇聚结果。

相对 v1.1（机构看入库量、运营配供数方、全平台一份标准文档），v1.2 强化：**标准拼装（全局/机构）**、**安全推送（appkey + 条件 IP 白名单）**、**推送副本落库与自动打标**；**数据外推**与**不区分机构的自有供数**仅预留。

### 1.2 建设目标

1. 运营维护元数据字段库与接入方案库，拼装发布全局标准；机构可覆盖为机构标准。  
2. 机构预览/下载本机构生效标准并转交供数方。  
3. 供数方按标准、凭 appkey（及必要时白名单 IP）向云数中台推送；中台单独落一份并自动打标（来源厂商、接收时间；本期区分机构）。  
4. 现有概览、供数统计等模块内容与交互保持不变。  

### 1.3 核心价值

- 先打通「定标准 → 推送 → 落库打标」主链，数据进得来、留得住、来源可追溯。  
- 标准可复用拼装，全局底稿 + 机构覆盖，减少一机构一文档的混乱。  
- 安全可控：供方凭证 + 按接入方案可选的 IP 白名单。  

### 1.4 使用端与交付

- **MT 管理端**：字段库、接入方案、标准拼装、供数方与 appkey、IP 白名单；既有供数配置等保持。  
- **V8 应用端**：生效标准预览/下载；既有数据概览、供数统计等保持。  
- **推送接入**：供数方系统调用中台接收能力（非机构操作界面）。  

### 1.5 与 v1.1 的关系

- **保留**：V8/MT 已有统计、供数方、机构供数配置等既有内容不删不改交互目标。  
- **演进**：接入标准由「单文件上传」演进为「字段库 + 接入方案库 → 拼装发布（全局/机构）」。  
- **新增**：appkey、IP 白名单、推送落库副本与自动打标。  
- **预留**：数据外推；不区分监测方案/不区分机构的平台自有供数。

## 三、核心模块设计

### 3.1 元数据字段库（数据标准素材）

运营维护可复用字段：字段名、业务含义、数据类型等属性。启用中的字段可供创建接入标准时勾选，组成该标准的「数据标准」块。

### 3.2 接入方案库

运营维护对接策略：前置机地址、推送频次、增量/全量规则等。增加开关：**是否需要 IP 白名单管控**。启用中的方案可供标准绑定（一份标准绑定一个接入方案）。

### 3.3 接入标准拼装（全局 / 机构）

- **全局标准**：平台底稿；平台侧明确当前启用的全局标准。  
- **机构标准**：某机构可在全局基础上选用/覆盖；有机构标准且启用时，该机构生效标准=机构标准，否则=当前全局标准。  
- **创建/发布**：勾选若干字段（数据标准块）+ 选择一个接入方案 → 发布。机构在 V8 预览/下载的是本机构**生效标准**的拼装结果。  
- 与供数方推送校验：按目标机构的生效标准及其绑定方案执行（含是否校验 IP 白名单）。

### 3.4 IP 白名单管理

运营维护允许推送的来源 IP（或网段，以落地 SRS 为准）。仅当**生效标准所绑定的接入方案**开启「需要白名单管控」时，推送请求的来源 IP 必须命中白名单，否则拒收且不落库。

### 3.5 供数方 appkey

一供数方一 appkey，由运营发放与轮换。推送必须携带有效 appkey；供数方停用则不可推送成功。

### 3.6 推送接收、落库与自动打标

1. 校验 appkey、（条件）IP 白名单、报文与生效标准字段要求、归属机构可解析。  
2. 通过后**单独落一份**推送数据副本。  
3. **自动打标**（无需人工配置）：来源厂商、接收时间；本期业务维度为**区分机构**（须落到归属机构）。  
4. 预留：数据域类型（区分机构 / 不区分机构）、外推相关状态。

### 3.7 既有模块（保持不变）

V8：数据概览、供数统计、供数方查看等既有内容与交互目标不变。  
MT：供数方管理、机构供数配置等既有内容与交互目标不变。  
接入规范/标准相关页面向「生效标准拼装结果的预览下载」演进，统计类页面不因此改版。

## 四、数据结构与流向

### 4.1 关键实体

| 实体 | 要点 |
|------|------|
| 元数据字段 | 字段名、业务含义、类型、启用状态等 |
| 接入方案 | 前置机、频次、增/全量、是否白名单管控、启用状态 |
| 接入标准 | 范围（全局/机构）、勾选字段列表、绑定方案、启用状态 |
| IP 白名单 | 允许的来源 IP |
| 供数方 | 含 appkey、启用/停用（既有供数方上扩展） |
| 落库副本 | 推送原文/报文；标：来源厂商、接收时间、归属机构；预留域类型与外推 |

### 4.2 主数据流

```
字段库 + 接入方案库 + IP白名单 + 供方appkey
  → 发布全局标准 / 机构标准
  → 机构下载生效标准并转交供方
  → 供方推送（appkey，必要时白名单 IP）
  → 校验通过 → 落库副本 → 自动打标
  → 【预留】外推
```

### 4.3 生效标准判定

1. 若该机构存在启用中的机构标准 → 使用该机构标准。  
2. 否则 → 使用当前启用的全局标准。  
3. 若全局亦无启用标准 → 机构侧提示未发布；推送侧无有效标准可拒收。

## 五、边界情况处理

| 场景 | 处理 |
|------|------|
| 机构无自有标准 | 使用当前启用全局标准 |
| 接入方案未开白名单 | 不校验来源 IP |
| 开了白名单但 IP 未登记 | 拒收，不落库 |
| appkey 无效或供方停用 | 拒收，不落库 |
| 无法解析归属机构 | 拒收或不落库（本期无「不区分机构」通道） |
| 标准未启用/未发布 | 机构端提示；推送无有效标准则拒收 |
| 既有统计模块 | 不改交互；有落库数据后可按既有口径展示 |
| 不区分机构供数 / 外推 | 仅预留，本期无业务操作入口 |

---

## 六、验收要点

1. 可维护字段库、接入方案（含白名单开关）、全局/机构标准拼装发布。  
2. 机构下载到的是本机构生效标准（有机构标准用机构，否则全局）。  
3. 合法 appkey 且（若需要）IP 在白名单内时可推送成功并落库，自动带上来源厂商与接收时间及归属机构。  
4. 白名单开启但 IP 未登记、或 appkey 无效时推送失败且不落库。  
5. 既有统计等模块界面与既有能力描述保持可用、未做破坏性改版。
