## 二、项目概述

### 2.1 项目背景

多厂商供数需要统一进入云数中台。领导沟通后，本期优先保证**数据能安全汇总落库**；分析统计深化后置。**已有统计与供数配置等模块保持当前内容不变**。在 V1.0「单份标准文档 + 入库量查看」基础上，标准改为可拼装的全局/机构标准，并增加推送安全与自动打标。

### 2.2 项目建设目标

1. 维护元数据字段库与接入方案库，拼装发布全局标准；机构可覆盖为机构标准或由机构供数配置绑定标准。  
2. 机构预览/下载本机构生效标准并转交供数方。  
3. **按接入路径识别来源厂商**：接口推送凭 appkey；库表/JDBC 直推凭行内供数方编码。  
4. 当生效标准绑定的接入方案开启白名单时，来源 IP 须在白名单内（安保，不单独作为厂商归属依据）。  
5. 校验通过后单独落一份副本，自动标注来源厂商、接收时间，并归属机构。  
6. 既有概览、供数统计等能力保持 V1.0 规格可用。  

### 2.3 建设范围

**系统端**：V8 应用端、MT 管理端、供数方推送接收能力（含接口与库表两类接入形态）。

**本期功能**：

- 新增/强化：字段库、接入方案库、接入标准拼装（全局/机构）、IP 白名单、供数方 appkey、**双路径来源厂商识别与落库打标**、V8 生效标准预览下载  
- 保持/微调：数据概览、供数统计、供数方查看、供数方管理（见 V1.0）；机构供数配置可绑定接入标准  
- 预留：不区分机构的自有供数通道、数据外推深化  

### 2.4 术语

| 统一用语 | 含义 |
|---------|------|
| 生效标准 | 优先取机构供数配置绑定的启用标准；否则有该机构启用中的机构标准则用之，再否则用当前启用的全局标准 |
| 数据标准块 | 标准中勾选的元数据字段集合 |
| 接入方案 | 可复用的对接策略（数据源类型、JDBC/频次、是否 IP 白名单等）；**不绑定供数方** |
| appkey | 一供数方一份接口推送凭证；**仅用于接口路径鉴权与来源识别** |
| 供数方编码 | 供数方主数据中的唯一编码；库表路径行内字段（如 `supplier_code`）须与此一致，用于识别来源厂商 |
| 落库副本 | 推送/抽数成功后单独保存的一份数据 |

### 3.5.4 接入规范（V8 · 生效标准）

**（一）功能需求概述**

机构管理员查看并下载本机构**生效标准**（数据标准块 + 接入方案信息），转交供数方按标准推送。

**（二）功能设计**

**查看**

| 字段 | 说明 |
|------|------|
| 生效范围 | 机构标准或全局标准 |
| 数据标准 | 标准中勾选字段及属性摘要 |
| 接入方案 | 所绑方案的数据源类型、JDBC/频次、增/全量、是否白名单管控等（方案不展示「适用供数方」） |
| 发布时间 | 该生效标准的发布时间 |
| 来源识别说明 | 向供数方说明：接口路径凭 appkey；库表路径须按行填写供数方编码 |

**下载 / 预览**

提供预览与下载。无任何可用生效标准时，不提供下载，提示联系平台运营。

**业务规则**

- 生效标准判定：机构供数配置已绑定且该标准启用 → 用绑定标准；否则有该机构启用中的机构标准 → 用之；否则用当前启用的全局标准。无单独提示。  
- 预览中的数据标准字段须能体现库表必填的供数方编码、归属机构标识等口径（与字段库一致）。无单独提示。  
- 各机构互不影响；仅本机构管理员可见本机构生效结果。无单独提示。  

**边界与异常**

- **空数据**：无生效标准 → 提示尚未发布，请联系平台运营  
- **权限不足**：平台运营在 V8 无此入口（不展示）  

### 3.5.7 元数据字段库（数据标准管理）

**（一）功能需求概述**

平台运营维护可复用数据标准字段，作为拼装接入标准时「数据标准」块的素材。

**（二）功能设计**

**列表与维护**

| 字段 | 说明 |
|------|------|
| 字段名 | 英文字段标识（如 `supplier_code`） |
| 描述 | 业务含义说明 |
| 数据类型 | 如 String / Int |
| 业务分类 | 如平台 / 作者 / 文章 / 标注 / 其它 |
| 必填 | 必填 / 非必填 / 未设置 |
| 长度 | 可选 |
| 状态 | 启用 / 停用 |

支持新增、编辑、启用/停用。停用后不可被新标准勾选；已被标准引用的历史标准展示不受影响。

**平台预置与强约束字段（汇聚识别）**

| 字段名 | 必填口径 | 说明 |
|--------|----------|------|
| supplier_code | 库表路径必填；接口路径建议与 appkey 交叉校验 | 对应供数方管理中的编码，用于识别来源厂商 |
| org_id（或同等归属机构标识） | 本期必填 | 一条只归属一个机构；多机构须分次按各机构标识送来 |

**业务规则**

- 拼装用于库表接入的标准时，数据标准块**必须包含**启用中的 `supplier_code` 与归属机构标识字段。提交失败时提示补全。  
- 字段库**不**承担「绑定某一供数方」职责。无单独提示。  

**边界与异常**

- **空列表**：提示暂无字段，请先新增  

### 3.5.8 接入方案管理

**（一）功能需求概述**

平台运营维护可复用的对接策略，供接入标准绑定。一份方案可被多份标准引用。

**（二）功能设计**

| 字段 | 说明 |
|------|------|
| 方案名称 | 业务名称 |
| 数据源类型 | 库表数据集 / 接口 / 非结构化 / 实时队列等 |
| JDBC 连接信息 | 库表类型时：库类型、主机端口、库名、Schema、账号等 |
| 抽取/推送频次 | 如实时 / 每小时 / 每日等 |
| 更新规则 | 增量 / 全量及增量字段等 |
| 是否需要 IP 白名单管控 | 是 / 否 |
| 状态 | 启用 / 停用 |

停用后不可被新标准绑定。

**业务规则**

- **接入方案不绑定供数方**；厂商归属不由方案决定。无单独提示。  
- 当「是否需要 IP 白名单管控」为是时，按该方案执行的接入须通过 IP 白名单校验。白名单用于来源安保，**不能单独作为来源厂商归属依据**。无单独提示。  

### 3.5.9 接入标准管理（全局 / 机构拼装）

**（一）功能需求概述**

平台运营拼装并发布全局或机构接入标准：勾选字段库中的启用字段，绑定一个启用中的接入方案。

**（二）功能设计**

**标准属性**

| 字段 | 说明 |
|------|------|
| 标准名称 | 业务名称 |
| 范围 | 全局 / 指定机构 |
| 数据标准块 | 勾选的字段列表 |
| 接入方案 | 绑定的一个方案 |
| 状态 | 启用 / 停用 |
| 发布时间 | 启用或发布时间 |

**启用规则**

- 全局：同时至多一份启用中的全局标准（新启用时原全局启用标准改为停用）。  
- 机构：同一机构同时至多一份启用中的机构标准。  

**业务规则**

- 创建时必须至少勾选一个启用字段，且必须绑定一个启用中的接入方案。提交失败时提示补全。  
- 当绑定方案为库表类型时，勾选字段须包含平台预置的供数方编码与归属机构标识字段。提交失败时提示补全。  
- 机构生效标准见 3.5.4。无单独提示。  

**边界与异常**

- **无启用字段或方案可选**：提示先至字段库或接入方案管理启用  

### 3.5.10 IP 白名单管理

**（一）功能需求概述**

平台运营维护允许向云数中台推送的来源 IP。仅在生效标准所绑接入方案开启白名单管控时参与校验。

**（二）功能设计**

支持新增、删除（或停用）白名单记录。列表展示已登记 IP。

**业务规则**

- 推送时若需白名单管控：来源 IP 未命中白名单 → 拒收，不落库。无单独对机构提示。  
- 未开启白名单管控时，不因 IP 拒绝。无单独提示。  

### 3.5.11 供数方 appkey

**（一）功能需求概述**

在供数方上维护一供方一 appkey，用于**接口推送**鉴权与来源识别。

**（二）功能设计**

| 能力 | 说明 |
|------|------|
| 查看 / 发放 | 为供数方生成或登记 appkey |
| 轮换 | 轮换后旧 key 失效 |

**业务规则**

- **接口路径**：推送必须携带有效 appkey，且对应供数方为启用。否则拒收，不落库。无单独提示。  
- **库表路径**：不校验、不使用 appkey；来源厂商识别见 3.5.12。无单独提示。  

### 3.5.12 接入接收、落库副本与自动打标（含来源厂商识别）

**（一）功能需求概述**

按生效标准接收供数方数据（接口推送或库表/JDBC 直推）；校验通过后单独保存一份副本，并自动打标。核心能力之一是**识别来源厂商**。

**（二）功能设计**

**来源厂商识别（双路径）**

| 接入路径 | 权威依据 | 说明 |
|----------|----------|------|
| 接口推送 | appkey → 供数方主数据 | 落库「来源厂商」取该 appkey 对应供数方；可与报文中的供数方编码交叉校验 |
| 库表 / JDBC 直推 | 行内供数方编码（`supplier_code`）→ 供数方主数据 | 无 HTTP 凭证；**不以接入方案、不以 IP 单独定厂商** |

**校验顺序（逻辑）**

*接口路径*

1. appkey 有效且供数方启用  
2. 若生效标准绑定方案要求白名单：来源 IP 在白名单中  
3. 能解析归属机构（本期仅支持区分机构）  
4. 报文满足生效标准数据标准块的必填口径  

*库表路径*

1. 行内供数方编码存在，且能对应到启用中的供数方  
2. 若生效标准绑定方案要求白名单：写入/抽数相关来源 IP 在该供数方白名单中（按白名单按厂商维护）  
3. 能解析归属机构  
4. 行数据满足生效标准数据标准块的必填口径（含供数方编码、归属机构标识）  
5. 若目标机构未在「机构供数配置」中勾选该供数方：可不计入该机构统计（与 V1.0 计入规则一致）；是否整批拒收由联调约定，默认**不计入该机构且可拒收无有效机构归属的记录**  

**落库与打标**

| 项 | 说明 |
|----|------|
| 落库副本 | 校验通过后保存一份 |
| 来源厂商 | 接口：取自 appkey 对应供数方；库表：取自供数方编码对应供数方 |
| 接收时间 | 自动取进入中台的时间 |
| 归属机构 | 自动取解析到的机构 |
| 预留 | 数据域类型、外推状态 |

**业务规则**

- 接入方案、接入标准**均不绑定唯一供数方**；同一方案/标准可供多个供数方、多个机构使用。无单独提示。  
- 库表路径缺少供数方编码、编码无法对应主数据、或对应供数方已停用：拒收该条（或该批按联调约定），不写有效落库副本。无单独提示。  
- 接口路径 appkey 无效或供方停用：拒收，不落库。无单独提示。  
- 任一关键校验失败：拒收，不写落库副本。无单独提示（可由接收回执说明原因，回执形态联调约定）。  
- 本期不提供「不区分机构」成功落库通道。无单独提示。  
- 自动打标无需人工配置。无单独提示。  

**边界与异常**

- **无法识别来源厂商**：拒收  
- **无法归属机构**：拒收  
- **无生效标准**：拒收  

**（三）业务逻辑关联**

- 依赖字段库（含供数方编码字段）、接入方案、标准启用、白名单、供数方主数据（编码与 appkey）、机构供数配置  
- 落库结果可供 V1.0 既有入库统计在数据具备后按原口径使用

| 项 | 要求 |

| 安全 | 鉴权、白名单或来源厂商无法识别时不得落库 |
| 一致 | 同一生效标准下，机构多次预览/下载内容一致 |
| 追溯 | 落库副本可区分来源厂商与接收时间；库表与接口路径打标规则可区分说明 |

---

## 五、验收标准

1. 可维护字段、接入方案（含白名单开关、不绑厂商）、全局/机构标准并启用。  
2. 机构可下载本机构生效标准；预览字段含供数方编码等口径。  
3. 接口：合法 appkey +（若需要）白名单 IP 推送成功，落库「来源厂商」等于该 appkey 对应供数方。  
4. 库表：行内合法供数方编码可识别来源厂商并打标；缺少/错误编码则失败不落库。  
5. appkey 无效、编码无法识别、需白名单但 IP 未登记、或无法归属机构时失败且不落库。  
6. 数据概览、供数统计等既有模块仍按 V1.0 可用，无破坏性改版。  

---

## 六、本期不做

- 将供数方绑定到接入方案或作为方案必填项  
- 仅靠共前置机来源 IP、无供数方编码即可认定厂商  
- 不区分机构 / 不区分监测方案的推送与落库通道实装  
- 数据外推深化（已有推送管理原型可继续迭代，不替代本条入库识别规则）
