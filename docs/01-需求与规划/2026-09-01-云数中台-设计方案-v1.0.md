# 云数中台设计方案

## 一、项目概述

### 1.1 项目背景

公司需汇聚多个厂商的舆情数据，供客户按业务需要自选使用，并在统一口径下对比各厂商的数据量、及时性与研判质量。现有产品仅作参考，云数中台作为第一套统一入口建设，不从既有系统迁移。

### 1.2 建设目标

1. 按「厂商 × 主题/领域 × 信源类型」为客户开通所需数据，原始舆情汇聚落库。
2. 在同一切片下对比供数质量，并回显厂商已有的轻量研判结果（如调性、区域），中台不代替厂商做研判、不改判。
3. 一期做成能力底座，不绑死政务或品牌等行业包；开放生态（外部接入、结果外推）放到后期。

### 1.3 核心价值

- 客户自选要哪些厂商、哪些主题/领域、哪些信源，而不是被动接收全量包。
- 同一套三维切片下比较数据量、占比、及时性（中台实测）、准确性（本租户抽检）以及调性/区域等分布。
- 原始数据落库，一期界面以看板和抽检为主，为后期明细查阅与生态预留基础。

### 1.4 使用端与交付

- 一期仅 PC Web，不包含移动端 H5。
- 多客户租户：平台统一维护厂商与数据目录，客户各自勾选开通，只查看本租户数据与抽检结果。

## 二、功能范围

### 2.1 一期与后期

| 模块 | 一期 | 后期 |
|------|------|------|
| 平台厂商与目录 | 维护厂商、主题/领域、信源类型 | 行业包、更细类目 |
| 供数接入 | 按开通范围汇聚落库（标题、正文、URL、时间、厂商研判字段等） | 更多接入方式 |
| 客户数据开通 | 三维组合勾选、启停 | 计量计费、配额 |
| 质量对比看板 | 按三维切片对比量、占比、及时性、准确性、调性/区域分布 | 自定义指标、下钻明细 |
| 抽检准确性 | 本租户取样、打对错、算准确率 | 平台级基准准确率 |
| 研判 | 只回显厂商结果并汇总，不改判 | 明细查阅、开放推送 |
| 生态 | 不做 | 外部数据接入、研判结果外推 |
| 权限 | 平台运营 / 客户管理员 / 客户研判员 | 更细数据范围 |

### 2.2 一期明确不做

- 在中台写结论、改调性、改等级。
- 研判员查看单条正文的工作台。
- 外部系统推送、开放 API 生态。
- 移动端 H5。
- 跨客户共享抽检准确率或平台统一排行榜。

### 2.3 角色与职责

| 角色 | 归属 | 一期职责 |
|------|------|----------|
| 平台运营 | 公司 | 维护厂商、主题、信源；配置对接；查看接入是否正常。不代替客户抽检。 |
| 客户管理员 | 租户 | 勾选开通组合；对本租户已开通数据抽检打对错；查看本租户看板。 |
| 客户研判员 | 租户 | 只看本租户对比看板。不下钻单条、不抽检、不改判。 |

数据、开通范围、抽检样本与准确率按租户隔离：A 客户不可见 B 客户的上述信息。

## 三、核心模块设计

### 3.1 平台：厂商与数据目录

平台运营维护三份主数据，客户开通时只能从中勾选：

- **厂商**：名称、状态（启用/停用）、对接标识。
- **主题/领域目录**：通用类目（如经济、民生、文旅），可启用/停用，不绑死行业。
- **信源类型**：新闻、微博、短视频等。

厂商停用后，已开通客户停止新数据入库；历史数据与已有看板统计仍可查看。

### 3.2 平台：供数接入

各厂商按约定将舆情数据推送至中台（或由中台拉取）。入库字段至少包括：

- 内容：标题、正文、URL、内容发布时间、到达中台时间。
- 三维：厂商、主题/领域、信源类型。厂商侧标签须映射到平台统一目录。
- 厂商研判回显：调性（正/中/负）、区域等。

未开通的组合不对客户可见（不入库或不授权该租户）。同一条物理内容可被多家厂商各报一次，按「厂商 + 内容标识」区分；一期不做跨厂商自动去重合并。

### 3.3 客户：数据开通

管理员面对三维组合清单（可按厂商、主题、信源筛选），勾选后开通。

- 开通后按该组合供数、进入看板、可被抽检。
- 可停用某组合：停止新数，已入库数据仍可用于按时间范围的历史对比。
- 未开通的组合不出现在研判员看板中。

### 3.4 质量对比看板（三维质量对比）

「三维」指厂商、主题/领域、信源类型；「质量对比」指在同一切片下横比各厂商指标。研判员与管理员按时间范围查看本租户已开通范围。默认先选主题 + 信源再横比厂商，也可先选厂商再看其下主题/信源。

每个切片展示：

- **数据量、占比**：该切片内各厂商条数及占比。
- **及时性**：内容发布时间（若无则用厂商推送时间）相对到达中台时间的延迟；展示分布（如中位数、分位，细则在 SRS 中确定）。
- **准确性**：本租户抽检得出的准确率；未抽检时显示「暂无抽检」。
- **研判分布**：调性正/中/负数量与占比；区域等分布（有值才展示）。

看板只读。研判员不能进入单条。

### 3.5 抽检与准确性（仅客户管理员）

- 从本租户已开通且已入库的数据中，按「组合 + 时间范围 + 抽取条数」生成样本。
- 管理员查看样本标题/正文/URL 及厂商给出的调性等，登记对/错。一期以调性对错为主；区域等对错可作为同一条上的可选项。
- 准确率 = 判定为「对」的条数 / 本租户该范围已完成抽检条数。
- 准确率仅用于本租户看板，不共享给其他客户，平台不出统一排行榜。
- 抽检不修改厂商原值，只记录抽检结论。

### 3.6 一期菜单与交互

**运营端**：厂商管理；主题/领域目录；信源类型；接入状态（最近入库量、延迟是否异常，便于运维）。

**客户端（管理员）**：数据开通；质量对比；抽检任务（创建 → 样本打对错 → 查看本租户准确率）。

**客户端（研判员）**：质量对比（与管理员同一看板，只读、无抽检入口）。

看板顶部筛选时间、主题、信源、厂商（多选，仅已开通项）→ 下方按厂商对比的卡片或表格；分布用条形或表格，不做复杂大屏。

## 四、数据结构与流向

### 4.1 数据流向

```
厂商供数 → 映射到平台三维目录 → 按客户开通范围写入本租户数据
                ↓
        汇总：量、占比、调性/区域分布、及时性（发布时间 vs 到达时间）
                ↓
        质量对比看板（管理员、研判员只读）

本租户入库数据 → 管理员抽检打对错 → 本租户准确率 → 写回看板
```

### 4.2 关键数据实体

| 实体 | 说明 |
|------|------|
| 租户 | 客户隔离单位，开通范围与抽检结果均挂在租户下。 |
| 用户与角色 | 平台运营、客户管理员、客户研判员。 |
| 厂商 | 平台主数据，含启用状态与对接标识。 |
| 主题/领域 | 平台通用类目，供开通与切片使用。 |
| 信源类型 | 平台主数据，如新闻、微博、短视频。 |
| 开通组合 | 租户勾选的「厂商 × 主题 × 信源」，含启用/停用。 |
| 舆情内容 | 标题、正文、URL、内容发布时间、到达中台时间、三维、厂商研判字段（调性、区域等）。 |
| 抽检任务 | 租户、组合、时间范围、抽取条数、状态。 |
| 抽检样本结论 | 关联内容与任务，记录对/错，不回写厂商原值。 |

### 4.3 口径摘要

- **数据量**：本租户已开通范围内，按切片统计入库条数。
- **及时性**：内容发布时间优先，缺省用厂商推送时间，与到达中台时间求延迟；两者皆无则该条不计入及时性，仍计入数据量。
- **准确性**：本租户抽检「对」条数 / 该范围已完成抽检条数。
- **调性分布**：按厂商回显的正/中/负汇总；空值不计入分布，仍计入数据量。

## 五、边界情况处理

| 场景 | 处理 |
|------|------|
| 客户未开通某组合 | 不向该客户供应该组合数据；看板无此切片。 |
| 厂商漏报主题/信源或无法映射 | 进入「未映射」缓冲，不对客户展示；运营补映射后，再按开通范围进入客户库。 |
| 无内容发布时间 | 及时性改用厂商推送时间；两者都无则该条不计入及时性，仍计入数据量。 |
| 调性为空 | 不计入调性分布，数据量仍计。 |
| 停用开通组合或停用厂商 | 停止新数据；历史统计仍可按时间范围查询。 |
| 尚未抽检 | 准确性显示「暂无抽检」，不影响数据量与及时性。 |
| 同一 URL 被多家厂商报送 | 各厂商分别计入量与质量，一期不去重合并。 |
| 研判员需要看正文 | 一期不提供明细；由管理员通过抽检查看样本。 |
| 跨客户对比厂商准确率 | 不做；无平台统一准确率、无跨租户排行。 |
| 平台运营误入客户抽检 | 运营端无客户抽检打标入口；抽检仅客户管理员可见。 |
